## Як запускати скрипт

Скрипт запускається **з Python 3** у терміналі (cmd / PowerShell на Windows,
bash на Linux) з каталогу, де лежить файл:

```
python opencode-backup.py <команда> [аргументи]
```

Приклади:
```
python opencode-backup.py list
python opencode-backup.py projects
python opencode-backup.py help --full
```

> **Важливо:** на Windows імена файлів у командному рядку з пробілами беруть у
> подвійні лапки: `python opencode-backup.py export ... "C:\my folder\s.yml"`.

База даних: `~/.local/share/opencode/opencode.db`
(на Windows це `C:\Users\<ім'я>\.local\share\opencode\`,
на Linux — `/home/<ім'я>/.local/share/opencode/`).

## Терміни

| Термін            | Що означає |
|-------------------|------------|
| **Сесія**         | Один діалог зі штучним інтелектом (один чат з назвою та історією) |
| **Проєкт**        | Група сесій, пов'язаних з однією текою/git-репозиторієм |
| **Project ID**    | Унікальний ідентифікатор проєкту (наприклад `04eb5a3827dfa1ae8de74d083cff855cb62379f1`); рахується з git-remote URL |
| **Архівація**     | OpenCode іноді «архівує» завершені сесії — вони зникають зі списку, але лишаються в базі (з міткою `time_archived`) |
| **Event log**     | Внутрішній журнал подій сесії; від нього залежить, чи сесія продовжиться після переносу |
| **Remap**         | Переписування збережених шляхів (напр. `C:\...` → `/home/...`) у базі |

## Коротка довідка команд

| Команда | Призначення | Приклад |
|---|---|---|
| `list` | Список заархівованих сесій | `python opencode-backup.py list` |
| `restore <id_або_текст>` | Відновити одну сесію з архіву | `restore ses_f94638q...` або `restore "умови"` |
| `restore-last` | Відновити останню заархівовану | `restore-last` |
| `restore-all` | Відновити всі заархівовані | `restore-all` |
| `projects` | Показати проєкти та к-ть сесій | `projects` |
| `check` | Перевірити, чи всі шляхи проєктів існують | `check` |
| `remap <старе> <нове>` | Переписати шляхи в базі | `remap C:/Users/Vasyl/proj /home/vasyl/proj` |
| `project-id [папка]` | Показати, який ID отримає папка | `project-id /home/vasyl/proj` |
| `archive-project <pid>` | Заархівувати сесії проєкту | `archive-project 04eb5a...` |
| `export [pid] [файл]` | Експорт сесій у JSON | `export 04eb5a... out.json` |
| `import <файл> [--force]` | Імпорт сесій з JSON | `import out.json` |
| `backup [файл]` | Повна копія бази (.db+.wal+.shm) | `backup D:\backups\oc.db` |
| `full-backup [-p pid] [-o zip]` | Все в одному zip (конфіг+auth+БД) | `full-backup -p 04eb5a... -o f.zip` |
| `full-restore <zip> [--dry-run] [--yes]` | Відновлення з zip на цьому ПК | `full-restore f.zip` |
| `help [--full]` | Довідка | `help` |

### Аліаси команд

Наступні пари команд ідентичні — можна писати будь-який із варіантів:

| Команда | Еквівалент |
|---|---|
| `check` | `path-check` |
| `project-id` | `project_id` |

## Ситуація 1: Сесія зникла з бічної панелі

OpenCode Desktop може **автоматично архівувати** завершені сесії: вони зникають
зі списку, але лишаються в базі. Повернути:

```
python opencode-backup.py list                     # подивитись, що в архіві
python opencode-backup.py restore-last             # останню архівовану
python opencode-backup.py restore ses_f94638q...   # за точним ID
python opencode-backup.py restore "умови приклад"  # за текстом з назви
```

Потім **перезапусти OpenCode Desktop**, щоб список оновився.

> 🔎 **Інтерактивний вибір:** якщо `restore "текст"` знаходить **декілька** сесій,
> скрипт виведе нумерований список. У терміналі можна ввести номер і натиснути
> Enter — відновиться саме та. (Приклад: `restore "session 13"` знайшов дві сесії
> → обираєш 1 або 2.)

### Заархівувати всі сесії проєкту

`archive-project` — зворотна операція до «відновлення»: позначає всі сезії
проєкту як архівовані (вони сховаються з панелі, але лишаться в базі):

```
python opencode-backup.py archive-project 04eb5a3827dfa1ae8de74d083cff855cb62379f1
```

Потім, якщо знадобиться, поверни їх назад: `restore-all` або `restore-last`.

## Ситуація 2: Перенесення всіх сесій на інший комп'ютер

Найповніший і найнадійніший спосіб — `full-backup` / `full-restore`. В одному
zip-файлі: налаштування, ключі API (auth.json) і вся база сесій. Працює в обидва
боки (Windows → Linux, Linux → Windows).

**Крок 1. На старому комп'ютері** зробити архів:

```
python opencode-backup.py full-backup -o opencode_full.zip
```

(без `-o` файл з'явиться у `~/.local/share/opencode/exports/`)

**Крок 2.** Скопіювати `opencode_full.zip` на новий комп'ютер
(флешка, scp, Syncthing, Dropbox — будь-як).

**Крок 3. На новому комп'ютері** відновити:

```
python opencode-backup.py full-restore opencode_full.zip
```

Скрипт запитає підтвердження (або додай `--yes`). Перед заміною він **сам зробить
резервні копії** всіх наявних файлів (`*.pre-restore-<дата>`), тож нічого не
губиться.

> 🔎 **Безпека:** перед реальним відновленням можна подивитись план дій без змін:
> ```
> python opencode-backup.py full-restore opencode_full.zip --dry-run
> ```
> Він покаже, куди і що буде відновлено, але **нічого не впише**.

**Крок 4.** Перевірити шляхи та, за потреби, ремапнути (див. Ситуацію 5):

```
python opencode-backup.py check
```

**Крок 5.** Перезапустити OpenCode. Готово.

> 🔎 **Корисно:** `full-backup` з `-o` створює **теку автоматично**, якщо її ще нема.

## Ситуація 3: Перенесення лише одного проєкту

Якщо твій комп'ютер містить кілька проєктів, а перенести треба лише один —
додай `-p <project_id>`:

```
python opencode-backup.py full-backup -p 04eb5a3827dfa1ae8de74d083cff855cb62379f1 -o project_only.zip
```

Архів міститиме: конфіг + auth + базу, **відфільтровану** лише до цього проєкту
(решта проєктів у копії бази буде вирізана). Це зменшує розмір і не тягне чужі
сесії на нову машину.

Подальші кроки — як у Ситуації 2 (копіювання, `full-restore`, `check`, ремап).

> ⚠️ **Порада для майбутнього:** зроби **повний** `full-backup` (без `-p`) перед
> тим, як щось експериментувати — це твоя «страховка».

## Ситуація 4: Точкове перенесення окремих сесій

`full-backup` переносить **проєкти**, а `export`/`import` переносять **конкретні
сесії** як JSON-файл. Зручно, коли треба «витягнути» одну-дві сесії з однієї
машини в іншу, не чіпаючи решту.

**На старій машині** експортуємо:

```
python opencode-backup.py export 04eb5a3827dfa1ae8de74d083cff855cb62379f1 my.json
python opencode-backup.py export         # усе одразу (без pid)
python opencode-backup.py export 04eb5a3827dfa1ae8de74d083cff855cb62379f1 C:\backup\my.json
```

**Переносимо JSON-файл** (невеликий, можна листом/флешкою).

**На новій машині** імпортуємо:

```
python opencode-backup.py import my.json
python opencode-backup.py projects        # перевірка: сесії на місці
```

`import` сам синхронізує внутрішні лічильники подій (`event_sequence`) — ті, що
раніше спричиняли «зависання». Докладніше — у Ситуації 6.

Після імпорту можуть виявитися відсутні шляхи (папки проєктів) — скрипт про це
попередить і порадить `check`/`remap` (Ситуація 5).

## Ситуація 5: Шляхи не збігаються

На Windows шляхи виглядають як `C:/Users/Vasyl/Documents/GitHub/...`, на Linux —
`/home/vasyl/Documents/GitHub/...`. Після переносу OpenCode шукатиме сесії за
старими шляхами. Перевірка та виправлення:

```
python opencode-backup.py check
```

Виведе щось на кшталт:
```
[MISSING] 04eb5a3827dfa1ae8de74d083cff855cb62379f1
    dir: C:/Users/Vasyl/Documents/GitHub/realtyua/main   -> не існує
```

Тепер ремап — переписати старий шлях на новий:

```
python opencode-backup.py remap C:/Users/Vasyl/Documents/GitHub/realtyua/main /home/vasyl/Documents/GitHub/realtyua/main --yes
python opencode-backup.py check      # тепер має бути [OK]
```

Ремап працює зі слешами `/` та `\` і **нечутливий до регістру**. Якщо шляхів
декілька — повтори для кожного.

> 🔎 **Корисно:** `remap` оновлює і `session.path`, і `project_directory` — це
> важливо, бо саме через них Desktop показує сесії.

## Ситуація 6: Після відновлення сесія «думає» і не відповідає

**Симптом:** сесія видно в списку, старі повідомлення читаються, але на нове
повідомлення нічого не відбувається («думає» і все). При цьому **нові** сесії
працюють.

**Причина (вже виправлена):** при імпорті подій не оновлювався лічильник
`event_sequence`, тож OpenCode дописував нову подію з номром `seq=0`, який уже
зайнятий, — і все «зависало».

**Що робити зараз:**

1. Переконатися, що використовується **оновлений** скрипт (версія після фікса).
2. Повторити імпорт того ж JSON-файлу:
   ```
   python opencode-backup.py import my.json
   ```
3. Перезапустити OpenCode.

Після фікса `import` сам синхронізує лічильники, тож у майбутньому це не виникне.

## Ситуація 7: Помилка через не-латинські символи в шляху

**Симптом:** команда падає з `Error: file or directory not found: С:\...`
або `Не вдалося знайти...`, хоча файл/тека точно є.

**Причина:** у шляху випадково опинилася **кирилична літера** (наприклад
`С:\backups\...` — з «С» кириличною, а не латинською `C`). Скрипт це виявляє
і підказує.

**Рішення:** набрати шлях ще раз, уважно з латинськими літерами:
```
C:\backups\opencode_full.zip     # C — латинська
```

---
## Ситуація 8: Резервна копія перед змінами

Перед будь-якою «небезпечною» операцією зручно мати повну копію бази:
```
python opencode-backup.py backup D:\backups\opencode_before.db
```
Це копіює `.db` разом з `-wal`/`-shm`. Також `full-restore` сам створює
`*.pre-restore-*` копії всього, що перезаписує.

## FAQ

**Q: На якому Python це працює?**
A: На Python 3 (3.8+). Тільки стандартна бібліотека — пакети встановлювати не треба.

**Q: Я десь накосячив після restore — як відкотити?**
A: `full-restore` перед заміною зберігає все як `*.pre-restore-<timestamp>` у тих
же теках (`~/.config/opencode/` і `~/.local/share/opencode/`). Знайди потрібний
файл і поверни його на місце вручну, або просто повтори `full-restore` з іншого
архіву.

**Q: Скільки можна переносити — туди і назад?**
A: Обидва напрямки працюють однаково. Головне: після `full-restore` обов'язково
зроби `check` і ремап, бо шляхи різні.

**Q: Чи загубляться дані при повторному import старого файлу?**
A: Ні. `import` пропускає сесії, які в базі вже **новіші** (мають більше подій),
щоб не затерти свіжі. Примусово — прапорець `--force`, але навіть він не вкорочує
лічильник подій.

**Q: Чи дозволено запускати на Linux і на Windows одним файлом?**
A: Так, файл один і той самий. Він сам визначає, де лежить база на кожній ОС.

**Q: Що робити, якщо після переносу проєкт видно, але сесій у ньому немає?**
A: Якщо `check` показує `[OK]` — відкрий в OpenCode Desktop **папку проєкту**
(File → Open Folder), а не «Default Project». Desktop показує сесії поточного
відкритого каталогу.

**Q: Як побачити повний синтаксис усіх команд, без гайда?**
A: Скрипт сам виводить довідку:
```
python opencode-backup.py help
python opencode-backup.py help --full
```
