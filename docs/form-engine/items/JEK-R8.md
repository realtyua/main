# JEK-R8 — EOL-нормалізація: `.gitattributes` + EOL-незалежний freshness-тест

Phase: 3 · Depends: BASE-5 · Repo: realtyua
Branch: `feat/JEK-R8-eol-normalization` · Worktree: `../worktrees/JEK-R8-eol-normalization`

Status: `review`

## Goal

Свіжий checkout на Windows дає той самий результат гейтів, що й Linux/CI:
`form-app-fresh.test.mjs` не залежить від EOL робочого дерева.

## Проблема (знайдено в BASE-5)

Свіжий worktree на Windows: **213/214**, падає
`the baked add-property page matches a fresh render of the config`.

Ланцюжок:

1. Системний git-конфіг `C:/Program Files/Git/etc/gitconfig`:
   `core.autocrlf=true` (типове для Git for Windows).
2. `.gitattributes` у репозиторії **відсутній** → жодних правил.
3. Блоб зберігається з LF, checkout на Windows переписує на CRLF.
4. `gen-form-app.mjs` перезаписує запечений фрагмент із власним змішаним EOL
   (у канонічному чекауті: 610 CRLF + 821 bare LF на 1431 рядків).
5. Тест порівнює байти «файл на диску» vs «свіжий рендер» → розбіжність.

У канонічному чекауті тест зелений лише тому, що файл там **уже**
перегенерований bake-ом після checkout. Тобто gate проходить випадково.

На Linux/CI (`autocrlf=false`) проблема не проявляється.

## Files

- `.gitattributes` (новий)
- `test/form-app-fresh.test.mjs` (або спільний helper нормалізації)
- за потреби — `_form-engine/tools/gen-form-app.mjs` (якщо вирішимо фіксувати EOL
  під час генерації)

## Варіанти рішення

**A. `.gitattributes` на весь репозиторій**

```gitattributes
* text=auto eol=lf
```

Плюс `git add --renormalize .`. Мінус: одноразова масова зміна EOL у всьому
репозиторії — величезний diff і ризик для legacy-файлів.

**B. Вузько + стійкий тест (рекомендовано)**

```gitattributes
# Generated by the Form Engine bake; must stay byte-exact.
_includes/form/app/** -text
assets/data/form-*.json -text
```

Плюс нормалізація EOL у тесті перед порівнянням (`replace(/\r\n/g, '\n')`).
Diff мінімальний, gate стає незалежним від платформи.

**C. Фіксувати EOL у генераторі**

`gen-form-app.mjs` пише виключно `\n`. Не лікує проблему, якщо git checkout уже
переписав файл на CRLF до запуску тесту — а він переписує.

Рекомендація: **B**, за потреби — B + C.
